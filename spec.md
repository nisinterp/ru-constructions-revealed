# Спецификация: «Constructions are Revealed in Word Distributions» на материале русского языка (проход 1)

## Задача

Воспроизвести метод **global affinity** из статьи Rozner, Weissweiler, Mahowald, Shain (EMNLP 2025,
https://aclanthology.org/2025.emnlp-main.108.pdf) на русском языке, заменив `roberta-large` на
`ai-forever/ruRoberta-large`.

Проверяемая гипотеза (аналог §5.1 статьи): **фиксированные слова конструкций (якоря) имеют высокую
global affinity**, то есть модель уверенно восстанавливает якорь по контексту. Эффект должен
проявляться сильнее, чем у слов в открытых слотах тех же предложений, и сильнее, чем у той же
словоформы вне конструкции.

Global affinity слова в позиции i — вероятность исходного слова при маскировании только этого
слова: `P_{s\{i}}^{(i)}(w_i)`.

## Объём

### Входит в проход 1
- Global affinity для якорей и заполнителей слотов в **30 отобранных конструкциях** Русского
  конструктикона (не во всех 4001) — см. «Данные».
- Две базовые линии:
  1. **якоря vs заполнители слотов** в тех же предложениях;
  2. **та же словоформа вне конструкции** (предложения из НКРЯ).
- Два способа обработки мультитокенных слов и их сравнение (см. «Метод»).
- Для изменяемых якорей два варианта: вероятность точной словоформы (основной) и вероятность
  лексемы (сумма по формам той же леммы).
- Срезы: по части речи якоря и по синтаксическому типу конструкции, плюс агрегаты без срезов.
- Короткая статья на русском языке в Typst.

### Не входит (явно)
- «так/настолько … что»: CEC vs EAP/AAP (§4), multi-that (§4.2), UMAP для EAP/AAP (§4.3). Это следующий
  проход, для него понадобится собственный датасет.
- Local affinity и JSD-матрицы (в проходе 1 не нужны).
- Аналоги MAGPIE (идиомы), NPN и comparative correlative (§5.2, §6).
- Другие модели (xlm-roberta и т. п.), дообучение, любые правки кода авторов.
- Срезы по CEFR и usage_label.

## Модель

- `ai-forever/ruRoberta-large`: архитектура RoBERTa, 355M параметров, BBPE-словарь на 50 257 токенов,
  чистый MLM-объектив. При первом скачивании зафиксировать commit hash ревизии HF и дальше
  использовать только его.
- Fast-токенизатор обязателен: разметка опирается на `offset_mapping`. Если `tokenizer.is_fast`
  ложно, остановиться.

## Данные

### Русский конструктикон (CC BY 4.0)
- Источник: https://github.com/constructicon/russian-data (`data/*.yml`, по одной конструкции на
  файл; 4001 конструкция, 17 004 примера всего). Полный корпус **не** используется — из него отобран
  фиксированный список.
- **Список для прохода 1: `data/selected_constructions.json`, 30 конструкций.** Отобраны из 2401
  конструкций с ≥5 примерами, размеченными слотами и непустым `syntactic_type_of_construction`: по
  одной на каждую комбинацию (топ-10 синтаксических типов) × (тип якоря: `func` — только служебные
  слова, `content` — только знаменательные, `mixed` — оба). Список зафиксирован и утверждён
  пользователем; при необходимости корректировок правится вручную, не пересобирается заново
  автоматически. 51 уникальная форма якоря, 150 примеров.
- Поле `name` содержит шаблон. **Якоря** — слова, записанные строчной кириллицей (`кто`, `же`,
  `знает`). Латинские метки (`Noun-Nom`, `Cl`, `VP`, `XP`, `PronPers-3.Acc`) — это слоты. `/`
  отделяет альтернативы, `( )` — необязательные части. Кириллица с морфологическим тегом через дефис
  (`знать-Pst`) — изменяемый якорь, задан леммой.
- Поле `examples`: слоты размечены скобками, например
  `[Чёрт]Cognizer [его]Topic знает, [где они сейчас]Content.`
- `kind` (`func`/`content`/`mixed`) в `selected_constructions.json` — независимая переменная среза
  по части речи якоря, задана дизайном отбора, а не вычисляется постфактум. pymorphy3 используется
  дополнительно — чтобы дать точный POS-тег каждому конкретному слову (якорю и заполнителю) для более
  тонкого сравнения внутри среза, но не заменяет `kind`.
- `syntactic_type_of_construction` — второй срез, уже сбалансированный отбором (10 типов, по 3
  конструкции на тип).

### НКРЯ (базовая линия 2)
- Официальный API: `https://ruscorpora.ru/api/v1/...`, документация
  https://ruscorpora.github.io/public-api/. Токен передаётся заголовком
  `Authorization: Bearer <token>` и лежит в `.env` как `RNC_API_TOKEN`. Ключ генерируется
  пользователем в личном кабинете.
- Основной подкорпус, **50 предложений на каждую уникальную словоформу-якорь** из
  `selected_constructions.json` (51 форма → до 2550 предложений). Формы берутся в том виде, в
  каком они реально встретились в примерах конструктикона: для якорей с тегом (`знать-Pst`) это
  наблюдаемые формы («знала»), а не лемма. Лимиты API не документированы, поэтому запросы идут
  последовательно с паузой, ответы кэшируются по одному файлу на форму
  (`data/raw/rnc/<форма>.jsonl`), повторный запуск ничего не перекачивает.
- Правило «вне конструкции»: для формы f выбрасываются предложения, в которых вместе с f встречаются
  все остальные якоря хотя бы одной конструкции, где f — якорь. Для конструкций с одним якорем такой
  фильтр невозможен; это ограничение описывается в отчёте.
- **Если API недоступен** (нет токена, ошибка авторизации, отказ сервера): считать всё остальное,
  а в результатах и статье явно указать, что базовая линия 2 не выполнена.

## Метод

### Сегментация и извлечение единиц
1. Из примера убрать скобочную разметку, запомнив символьные спаны слотов. Остаётся чистый текст
   и список спанов с ролями.
2. Слова — подстроки между пробелами без начальной и конечной пунктуации. Дефисные слова («кто-то»)
   считаются одним словом. Регистр при сопоставлении не учитывается.
3. Каждое слово получает тип:
   - `anchor` — вне скобок и совпадает с якорем из `name`. Буквальный якорь сравнивается по
     словоформе, якорь с тегом — по лемме (pymorphy3). Из альтернатив засчитывается та, что
     реально встретилась. Необязательные части — только если присутствуют;
   - `filler` — внутри скобок-слота;
   - `other` — всё остальное. **Через модель не прогоняется** (при таком масштабе не нужен для
     анализа); подсчитывается только для статистики длины предложений и доли размеченных слов.
4. Слова сопоставляются с токенами через `offset_mapping` fast-токенизатора. Никаких проверок в
   духе `[a-zA-Z]`: ровно этот баг ломает код авторов на кириллице.
5. Пример длиннее 512 токенов пропускается и учитывается в логе исключений. Все исключения
   логируются с причиной.

### Global affinity: два варианта
- **single** (как в статье): слово однотокенно → маскируется один токен и берётся
  `softmax(logits)[orig_id]`. Мультитокенное слово пропускается с пометкой `multitoken`.
- **chain** (расширение): маскируются все k подтокенов слова, затем они раскрываются слева
  направо истинными токенами, а будущие подтокены того же слова остаются замаскированными:
  `P(w) = Π_i P(t_i | контекст, t_<i открыты, t_>i замаскированы)` (k прогонов модели, ср.
  PLL-word-l2r у Kauf & Ivanova 2023). При k=1 результат обязан совпадать с single — это
  юнит-тест.
- **Вариант по лемме** (только для якорей, только в single-режиме): сумма вероятностей всех
  однотокенных элементов словаря, которые являются формами той же леммы (pymorphy3) и имеют тот же
  префикс пробела, что исходный токен. Таблица «id токена → леммы» строится один раз по словарю.
  Это нижняя оценка, так как мультитокенные формы не учитываются.

### Анализ
- **Основное сравнение: якоря vs заполнители.**
  - Пул слов: Mann–Whitney U и Cliff's delta.
  - Уровень конструкций: для каждой конструкции разность «средняя affinity якорей минус средняя
    affinity заполнителей», доля конструкций с разностью > 0, sign test.
  - Доверительные интервалы — бутстрап по конструкциям (слова внутри конструкции зависимы).
  - Считается отдельно для single и chain.
- **Внутри vs вне конструкции** (базовая линия 2): для каждой словоформы-якоря средняя affinity
  в конструктиконе и средняя в НКРЯ; тест Уилкоксона по формам.
- **Мультитокенность:** доля мультитокенных среди якорей, заполнителей и other; как меняются
  выводы при переходе с single (только однотокенные) на chain (все слова).
- **Срезы:**
  - **Часть речи.** Определяется pymorphy3 для каждого слова, и якоря, и заполнителя. Внутри одной
    части речи якоря сравниваются с заполнителями той же части речи. Это контроль важного
    смешения: якоря — чаще служебные слова (предсказуемы сами по себе), а заполнители — чаще
    знаменательные. Без этого среза главный эффект может объясняться одной лишь частью речи.
  - **`syntactic_type_of_construction`.**
  - В каждом срезе приводятся медиана и доля affinity > 0.5 для якорей против заполнителей.
- Конструкции, в примерах которых нет ни одного размеченного слота (нечего сравнивать), в
  сравнение на уровне конструкций не входят, но их якоря остаются в пуле слов. Число таких
  конструкций — в отчёте.
- **Качественный разбор:** 15 якорей с самой низкой и 15 заполнителей с самой высокой affinity
  (из ~300–600 слов пула), с предложением и топ-5 предсказаниями модели (аналог разбора ошибок в
  статье).

## Быстрые проверки (fail in 30 seconds)

1. **Токенизатор:** загрузить токенизатор ruRoberta-large, проверить `is_fast`; на предложении
   «Бог его знает, где они сейчас.» спаны слов должны точно восстанавливаться из `offset_mapping`.
2. **Одна affinity:** на CPU посчитать global affinity для «знает» в этом предложении. Значение
   конечно и лежит в [0, 1]; сумма softmax по словарю равна 1; chain при k=1 совпадает с single.
3. **Доля однотокенных:** на 100 случайных примерах напечатать долю однотокенных якорей и
   заполнителей. Это ранний сигнал масштаба проблемы мультитокенности.
4. **НКРЯ:** `GET /api/v1/auth/check-authenticated` плюс один запрос по форме «знает» возвращают
   хотя бы одно предложение.
